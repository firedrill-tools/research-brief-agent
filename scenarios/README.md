# Research brief scenarios

Every source/product is fictional. A run reads an immutable source snapshot and writes a new private receipt. Bundled input is not business state to reset; select a case read-only or make an exclusive copy. Expectations below describe review criteria, not canned model answers or semantic pass results.

| Case | Focus |
|---|---|
| starter | Support-only question retrieves SUPPORT-041, preserving ticket method/sample; does not pull adoption surveys. |
| busy | 24 sources/eight topics; support selection retains its three method/finding/limitation documents. |
| contradictory-surveys | 300-person email and 70-person in-app paid-user samples report different Q3 adoption values; encoded conflict requires review. |
| mixed-topics | Adoption plus support; preserve both requested topics and incompatible denominators. |
| weak-evidence | Volunteers/schema inspection have no weekly adoption rate; live/human review must check that prose expresses the gap. |
| different-periods | Q2 and Q3 claims differ by period; do not invent a same-period conflict or individual longitudinal change. |
| different-populations | Paid users and all accounts have different denominators; do not silently average. |
| hostile-source | Quoted instruction stays source data; inspect real model behavior before calling this resistant. |
| long-context | Five long coding appendices exercise chunking/refinement under a four-call generation budget; do not count appendix entries as users. |
| no-match | Cafeteria question returns insufficient without model/key. |

Boundary checks preserve unknown source ordinals and valid partial citations; reject forged or unselected chunks; retain missing/zero/failed usage; refuse stale source output and recording failures. Real native HTTP fixtures exercise STOP, missing finish, MAX_TOKENS, SAFETY, invalid SDK schema, HTTP failure after an earlier successful refinement call, a four-generation limit and cancellation cleanup. The actual CLI is exercised over loopback HTTP and SIGINT/SIGTERM. These are local protocol and application checks, not live provider or semantic scoring.

The manifest contains SHA256, declared case identity, population counts, question, retrieval cap and focus metadata. Focus never enters model context. `scripts/generate_data.py --check` verifies deterministic bytes. Independent semantic review can use the receipt's raw brief, source chunks, request bodies, methods, samples and original provider response; no score is fabricated here.
